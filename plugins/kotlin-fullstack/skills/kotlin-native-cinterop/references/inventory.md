# Every binding in the portfolio, and what each one paid

Referenced from [SKILL.md](../SKILL.md). Read on `origin/main` of each repository on 2026-10-01; the
sha is the commit the row was read at. A row says how the library is built and pinned, which flags
live in the `.def` and which in Gradle, what the published klib carries, how a consumer links, how
it is tested, and what broke. When a row and the repository disagree, the repository is right and
this row is stale.

## Learned from private work, not named

Two services in a private study bind system libraries dynamically — a legacy spreadsheet reader and
two image codecs. What they add to the table above:

* **`compilerOpts = -idirafter /usr/include`, not `-I`.** With `-I`, the distribution's headers
  shadowed the sysroot's libc, and the first `limits.h` looked for headers of the new glibc that the
  sysroot does not have (`bits/libc-header-start.h`).
* **An error reported by `longjmp` stays in C.** libpng reports a corrupt file by jumping to a
  `setjmp` point; a jump across Kotlin/Native frames is undefined behaviour, so every libpng call
  sits in C after `---` with its own `setjmp`, returning a code and a message.
* **A buffer the library allocated is freed by the library.** turbojpeg has its own allocator, so
  its buffers go back through `tjFree`, not `free`.
* **The build machine needs the `-dev` package, the image needs the runtime package**, and the
  `.def` says which in a comment.
* A tests-in-release run caught a serializer fallback that worked only in the debug test binary —
  the same class as mongkn M-91.
