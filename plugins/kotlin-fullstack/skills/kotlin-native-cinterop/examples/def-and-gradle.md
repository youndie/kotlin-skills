# The `.def` and the Gradle block, in the two shapes that ship

Referenced from step 4 of [SKILL.md](../SKILL.md). Trimmed from the repositories named over each
block, comments shortened; read there for the full reasoning. The two shapes differ in where the
library comes from, and that decides where every flag lives.

## Shape 1: static archives carried in the klib (kafkakn)

`kafkakn@bd3193e:kafkakn-core/src/nativeInterop/cinterop/rdkafka.def`

```properties
# No paths here: include and library directories come from Gradle, so this file is the same on
# every machine and a second native target costs a build-matrix row, not an edit.
headers = librdkafka/rdkafka.h
headerFilter = librdkafka/**
package = rdkafka

# THE ARCHIVES GO INTO THE KLIB. Names only; cinterop copies them into
# default/targets/<target>/included/, and a consumer links with no configuration.
staticLibraries = librdkafka-static.a libssl.a libcrypto.a libz.a libzstd.a
```

`kafkakn@bd3193e:kafkakn-core/build.gradle.kts`

```kotlin
fun KotlinNativeTarget.rdkafka(bundleDir: String) {
    val interop = compilations.getByName("main").cinterops.create("rdkafka") {
        definitionFile.set(file("src/nativeInterop/cinterop/rdkafka.def"))
        includeDirs("$bundleDir/include")
        // Where the archives named in the .def are found — at cinterop time only.
        extraOpts("-libraryPath", "$bundleDir/lib", "-libraryPath", "$bundleDir/lib64")
    }
    // Gradle cannot see through extraOpts: without this a rebuilt bundle left the klib
    // carrying the old archives (B-39).
    tasks.named(interop.interopProcessingTaskName) {
        inputs.files(fileTree(bundleDir) { include("lib/*.a", "lib64/*.a") })
    }
    // NO linkerOpts, and their absence is the check: this project's own test binaries now
    // link exactly the way a stranger's do (B-13).
}

kotlin {
    jvm()
    linuxX64 { rdkafka(bundle) }
    if (withLinuxArm64) linuxArm64 { rdkafka(linuxArm64Bundle) }   // its own bundle, its own path
}
```

and in `gradle.properties`, once a second native target shares `nativeMain`:

```properties
kotlin.mpp.enableCInteropCommonization=true
```

## Shape 2: a system shared library (smtpkn, mongkn)

The paths differ between Homebrew and Debian, so they are resolved in Gradle — and then **written
into a generated copy of the `.def`**, because they must reach the klib's manifest.

`smtpkn@a89c6d7:smtp-tls-openssl/src/nativeInterop/cinterop/openssl.def` (the source)

```properties
headers = openssl/ssl.h openssl/err.h openssl/bio.h openssl/x509v3.h openssl/opensslv.h
headerFilter = openssl/**
package = openssl

---

// SSL_set_tlsext_host_name(s, n) is a function-like macro, and cinterop does not see those.
static int kmp_ssl_set_tlsext_host_name(SSL *ssl, const char *name) {
    return (int) SSL_set_tlsext_host_name(ssl, name);
}
static int kmp_tls1_2_version(void) { return TLS1_2_VERSION; }
static int kmp_ssl_error_want_read(void) { return SSL_ERROR_WANT_READ; }
```

smtpkn's own comment says "everything below is a macro … cinterop does not see macros". That
holds for the function-like one. `TLS1_2_VERSION` and `SSL_ERROR_WANT_READ` are object-like
constants, and cinterop binds those as `const val`
([probe](boundary-probes.md#macros)). Their shims are harmless and unnecessary.

`smtpkn@a89c6d7:smtp-tls-openssl/build.gradle.kts` (abridged)

```kotlin
val generatedDefinition: File =
    layout.buildDirectory.file("cinterop/openssl.def").get().asFile.also { file ->
        val source = file("src/nativeInterop/cinterop/openssl.def")
        // No `-Wl,`: options from a .def go straight to ld.lld.
        // --allow-shlib-undefined: the distribution's libssl references glibc symbols newer than
        // Kotlin/Native's sysroot; the loader resolves them at start. A consumer links against the
        // same sysroot and the same libssl, so the flag travels too.
        val allowUndefined = if (HostManager.hostIsLinux) "--allow-shlib-undefined " else ""
        val searchDirs = opensslLibDirs.joinToString(" ") { "-L" + it.absolutePath }
        // Properties go BEFORE `---`: below it is C, where `#` is a preprocessor directive.
        val (properties, code) = source.readText().split("\n---\n", limit = 2)
        file.parentFile.mkdirs()
        file.writeText(
            properties +
                "\n# Generated by build.gradle.kts; edits here are overwritten.\n" +
                // -L inside linkerOpts, not only libraryPaths: libraryPaths never reaches the
                // consumer's link (mongkn measured `unable to find library` without it).
                "linkerOpts = $allowUndefined$searchDirs -lssl -lcrypto\n" +
                "libraryPaths = ${opensslLibDirs.joinToString(" ") { it.absolutePath }}\n" +
                "---\n" + code,
        )
    }

kotlin {
    targets.withType<KotlinNativeTarget>().configureEach {
        compilations.getByName("main").cinterops.create("openssl") {
            definitionFile.set(generatedDefinition)
            includeDirs(*opensslIncludeDirs.toTypedArray())   // include/ AND include/<triplet>/
        }
        // No linker options here: while they lived here, our binaries linked and a consumer's did not.
    }
}
```

The absolute `-L` written into the manifest is the publishing machine's; it works for consumers on
the same distribution layout and is one more reason the image and the build machine are one
distribution version. On a Linux host this module declares only `linuxX64`, on a Mac only
`macosArm64` — the headers and the `.so` are the host's.

## Inline C that must be global: a static library, not `---`

`kotlin-native-rt@52a5a93:iconv/build.gradle.kts` compiles the C into an archive and generates the
`.def`, because code after `---` is compiled into the program's bitcode and `__wrap_*` functions
become local:

```kotlin
val compileC = tasks.register<Exec>("compileIconvUnicode") {
    // cc -O2 -fPIC ... -c iconv_unicode.c -o iconv_unicode.o && ar rcs libiconv_unicode.a ...
}
val generateDef = tasks.register("generateDef") {
    doLast {
        defPath.get().asFile.writeText("""
            |package = io.github.youndie.iconv.unicode.internal
            |staticLibraries = libiconv_unicode.a
            |libraryPaths = $libDir
            |linkerOpts = --wrap=iconv_open --wrap=iconv --wrap=iconv_close
            |""".trimMargin())
    }
}
tasks.matching { it.name == "cinteropIconvUnicodeLinuxX64" }.configureEach { dependsOn(generateDef, compileC) }
```

A module whose only content is a binding still needs one `.kt` file, or no klib is produced and the
publication fails.

## A signal handler: C, and nothing but an atomic store

`kore@c6d00a4:kore-core/src/nativeInterop/cinterop/koreSignal.def`

```c
package = io.github.youndie.kore.signal.native
---
#include <signal.h>

static int kore_raised_value = 0;

/* The FIRST signal names the shutdown. Nothing here enters the Kotlin runtime. */
static void kore_on_signal(int signo) {
    int expected = 0;
    __atomic_compare_exchange_n(&kore_raised_value, &expected, signo, 0,
                                __ATOMIC_SEQ_CST, __ATOMIC_SEQ_CST);
}

static inline void kore_install_signal_handlers(void) {
    signal(SIGTERM, kore_on_signal);
    signal(SIGINT, kore_on_signal);
}

static inline int kore_raised_signal(void) {
    return __atomic_load_n(&kore_raised_value, __ATOMIC_SEQ_CST);
}

/* What the test asserts: the installed handler IS this function. */
static inline int kore_handler_is_installed(int signo) {
    struct sigaction current;
    if (sigaction(signo, 0, &current) != 0) return 0;
    return current.sa_handler == kore_on_signal;
}
```

Kotlin polls `kore_raised_signal()` from a coroutine. Declared on Linux targets only
(`.matching { it.konanTarget.family == Family.LINUX }`), because the macOS cinterop would have been
silently skipped on the Linux host the library is released from.

## A variadic function behind a fixed signature

A variadic C function binds as `vararg variadicArguments: Any?` — `printf` in `platform.posix` has
exactly that shape — and each argument's C type is taken from the Kotlin value passed, with nothing
checking it against what the callee reads. When the library has no non-variadic sibling, give the
call a fixed signature in C. A fictional library, written for this repository:

```c
headers = ev.h
package = ev
---
/* ev_emit(ev, EV_V_TOPIC(name), EV_V_VALUE(ptr, len), EV_V_END): tag/value pairs built by
   function-like macros, which cinterop does not see. Their casts — (size_t), (int64_t) — are
   exactly what a Kotlin vararg call gets wrong without a word. The shim fixes the types once, in C. */
static inline int ev_emit_value(ev_t *ev, const char *topic, const void *value, size_t len) {
    return ev_emit(ev, EV_V_TOPIC(topic), EV_V_VALUE(value, len), EV_V_END);
}
```
